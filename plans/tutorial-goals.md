# 튜토리얼 목표 SSOT (초안)

> 모든 후속 정합성 감사·재설계의 기준선. 여기 적힌 목표가 ground truth.
> 사용자 검토 후 확정 → 이후 변경은 git 히스토리로 추적.

## §0. 제품의 핵심 가치 (criterion of all criteria)

**nost = 작업 컨텍스트(앱·URL·폴더·메모)를 카드로 모아두고, 키 한 번/클릭 한 번으로 즉시 호출하는 런처.**

따라서 모든 튜토리얼은 다음 셋 중 하나에 기여해야 한다:
1. **카드를 모은다** (capture)
2. **카드를 정리한다** (organize)
3. **카드를 빠르게 호출한다** (recall)

이 셋과 무관한 기능은 튜토리얼에 들어가지 않는다.

추가로 위 셋이 손에 익으려면 nost **자체**를 운용할 줄 알아야 한다 (단축키로 부르고, 업데이트를 받고, 호출 키를 내 손에 맞게). 이건 별도의 *지원 축*으로 `system` 섹션에서 다룬다.

## §1. 섹션 목표 (6개)

### 1.1 `basics` — 기본기
**목표**: 스페이스를 만들고, 그 안에 카드를 만들어, 한 번 클릭에 실행할 수 있다. 프리셋 1·2·3로 작업환경을 통째로 바꿀 수 있다. `/`로 즉시 검색할 수 있다.

**왜 이 섹션이 존재**: nost를 처음 켠 사람이 "이 도구로 뭘 할 수 있나"를 5분 안에 체험. 이 섹션 끝나면 일반 런처(macOS Spotlight, Windows Search)와의 차이를 손으로 안다.

### 1.2 `cards` — 카드 추가의 5가지 길
**목표**: 직접 입력 외에 4가지 빠른 추가 방법(스마트 스캔 / 클립보드 게이트웨이 / 드래그앤드롭 / 메모 변환)을 알고, 상황에 맞는 가장 빠른 길을 고를 수 있다.

**왜 이 섹션이 존재**: 카드 추가가 귀찮으면 nost를 안 쓰게 된다. "가장 빠른 추가 경로는 상황에 따라 다르다"를 가르치는 게 핵심.

### 1.3 `layout` — 공간 정리
**목표**: 카드와 스페이스의 위치를 바꿀 수 있고, 여러 카드를 묶어 한 번에 실행하는 노드 그룹을 만들 수 있다.

**왜 이 섹션이 존재**: 카드 수가 많아질 때 정리되어 있지 않으면 빠른 호출이 무너진다. 정리 능력은 30개 이상의 카드를 가진 사용자에게 필수.

### 1.4 `advanced` — 심화 호출
**목표**: 플로팅 뱃지로 nost 창 없이 화면에서 직접 호출하고, 노드 그룹으로 여러 카드를 동시 실행하며, 카드를 다른 프리셋으로 옮길 수 있다.

**왜 이 섹션이 존재**: nost를 일상 도구로 흡수한 사용자가 "창 띄우기" 자체도 줄이고 싶어질 때 필요한 기능. basics·cards·layout 다 끝낸 사람의 다음 단계.

### 1.5 `widgets` — 활성 카드
**목표**: 음악·컬러·메모 위젯이 카드 슬롯 안에서 동작하는 미니 도구임을 알고, 각각의 핵심 동작(미디어 키 / hex 복사 / 마크다운 메모)을 사용할 수 있다.

**왜 이 섹션이 존재**: 위젯은 nost의 "카드 = 즉시 실행" 모델을 확장한 형태. 위젯이 일반 카드와 다르다는 걸 모르면 발견되지 않는다.

### 1.6 `system` — nost 자체 운용 (신규)
**목표**: 단축키 한 번으로 nost를 호출·숨길 수 있고, 호출 키를 내 손에 맞게 바꾸거나 기본값을 유지할 수 있으며, 설정에서 업데이트를 직접 확인할 수 있다.

**왜 이 섹션이 존재**: capture/organize/recall이 빠르게 일어나려면 nost 자체의 입출력이 손에 붙어야 한다. 단축키를 모르고 있으면 매번 마우스로 작업표시줄에서 찾아 누르게 되어 nost의 가치 자체가 무너진다. 업데이트는 발견되지 않으면 사용자가 옛 버전에 머문다.

## §2. 퀘스트 목표 (21개) — "X를 Y 방법으로 할 수 있다"

### basics (4)
| ID | 목표 |
|---|---|
| `basics.spaces` | 헤더의 + 아이콘으로 스페이스를 추가하고 이름을 바꿀 수 있다 |
| `basics.cards` | + 추가 다이얼로그로 URL 카드를 만들고 클릭 한 번으로 실행할 수 있다 |
| `basics.presets` | 상단 1·2·3 토글로 독립된 작업환경 사이를 전환할 수 있다 |
| `basics.search` | `/` 또는 검색창에 카드 이름을 입력해 즉시 실행할 수 있다 |

### cards (5)
| ID | 목표 |
|---|---|
| `cards.scan` | 사이드바 전구 → 추천 패널에서 현재 열린 앱·탭을 카드로 추가할 수 있다 |
| `cards.clipboard` | URL/경로/hex를 복사한 뒤 게이트웨이 배너 버튼으로 카드를 만들 수 있다 |
| `cards.memo` | GPT/Notion 답변을 복사한 뒤 게이트웨이의 "메모로" 버튼으로 마크다운 메모를 만들 수 있다 |
| `cards.dragdrop` | Explorer/브라우저에서 파일·URL을 nost 위로 끌어 카드를 만들 수 있다 |
| `cards.dialog` | + 추가 다이얼로그의 3-페이즈(유형→값→위치)를 알고 화면 픽 모드를 활용할 수 있다 |

### layout (3)
| ID | 목표 |
|---|---|
| `layout.cardmove` | 카드를 우클릭 드래그로 다른 위치/스페이스로 옮길 수 있다 |
| `layout.spacereorder` | 스페이스 헤더를 좌클릭 드래그로 위·아래로 옮길 수 있다 |
| `layout.tile` | 사이드바 노드 모드에서 카드 2-3개를 묶어 노드 그룹을 만들 수 있다 |

### advanced (3)
| ID | 목표 |
|---|---|
| `advanced.floating` | 카드 우클릭 → "플로팅으로"로 화면 상주 뱃지를 만들 수 있다 |
| `advanced.nodegroup` | 노드 그룹에 단축키를 할당해 묶인 카드들을 동시에 실행할 수 있다 |
| `advanced.preset` | 카드 다이얼로그의 프리셋 칩으로 카드를 다른 프리셋으로 이동할 수 있다 (Pro) |

### widgets (3)
| ID | 목표 |
|---|---|
| `widgets.music` | 음악 위젯 카드로 재생/일시정지·트랙 이동·볼륨을 조작할 수 있다 |
| `widgets.color` | 컬러 위젯 카드 클릭으로 hex를 복사하고 swipe로 보색·유사색을 복사할 수 있다 |
| `widgets.memo` | 메모 위젯 + 에디터의 정리 도구 팔레트로 마크다운을 정리할 수 있다 |

### system (3, 신규)
| ID | 목표 | 비고 |
|---|---|---|
| `system.shortcut-toggle` | 기본 단축키로 nost를 호출하고 다시 숨길 수 있다 | 가장 기본. 다른 system 퀘스트의 prereq |
| `system.shortcut-custom` | 설정 → 단축키에서 호출 키를 내 손에 맞게 바꾸거나 기본값을 유지하기로 결정할 수 있다 | "기본 유지" 분기 — 첫 step에서 사용자가 "그대로 두기"를 누르면 변경 step을 건너뛰고 wrap으로. 강제로 키를 바꾸게 만들지 않음 |
| `system.update` | 설정 → 업데이트 확인 버튼으로 새 버전을 직접 받을 수 있다 | 결과(최신 / 새 버전 있음 / 오프라인) 상관없이 동작 자체를 익힘 |

## §3. 의도적으로 빠진 기능 (scope guard)

이번 라운드에 튜토리얼이 **없는** 기능과 그 이유:

| 기능 | 이유 |
|---|---|
| 핀 모드 (sidebar 핀) | 플로팅과 기능 중복, "플로팅으로"가 더 자연스러운 진입점 |
| 청소 모드 | 발견하면 직관적, 별도 학습 곡선 없음 |
| 덱 (deck) 모드 | 노드 그룹과 사용 패턴 비슷, 우선 노드만 |
| 카드 우클릭 메뉴 전체 | 메뉴 자체는 발견 가능, 핵심 항목(플로팅/이동)만 advanced에서 다룸 |
| 슬롯/컨테이너 카드 | 고급 사용자 패턴, 별도 섹션 필요 시 v2에서 |
| 템플릿/시작 키트 | 온보딩 흐름의 일부, 튜토리얼이 아님 |
| 백업/내보내기 | 안정성 기능, 학습 대상 아님 |
| 테마 다크/라이트 | 발견 가능, 학습 곡선 없음 |
| 스페이스 색·아이콘 변경 | 발견 가능, 학습 곡선 없음 |

## §3.5. 추가 제안 (사용자 결정 필요 — accept/reject)

코드 훑으면서 "이거 빠져 있는 게 의외다" 싶은 항목:

### 제안 A — `basics.slash` 또는 `system.slash` (슬래시 명령)
**현재 상태**: `basics.search`에서 "/로 명령어 실행 가능"이라고 한 줄 언급만. 실제 슬래시 명령 모드(`/help`, `/settings`, `/new` 등)는 별도 학습 surface 없음.

**제안 목표**: "검색창에 `/`로 시작하는 명령어를 입력해 마우스 없이 설정·새 카드·도움말 등에 접근할 수 있다"

**왜 가치 있나**: nost를 키보드 중심으로 쓰는 사용자에겐 슬래시 모드가 핵심. 모르면 영영 발견 안 됨. 분량 작은 quest 1개(3 step) 분량.

**소속**: `basics`(검색의 일부) 또는 `system`(키보드 운용 도구) 둘 다 합리적. 권장: `basics`에 추가 (basics.search 직후).

→ **결정**: 추가 / 보류

### 제안 B — `system.shortcut-custom`을 분리하지 말고 toggle과 한 quest로 묶기
shortcut-toggle (3 step) + shortcut-custom (3-4 step)이 합쳐도 5-6 step 분량. 사용자가 단축키를 "체험"하고 바로 "내 손에 맞게 바꾸기"로 가는 게 더 자연스러울 수 있음. 분리 시 reward는 1d씩 두 번 = 분리 보상이 의미 있다면 유지.

→ **결정**: 분리(현 안) / 통합

### 제안 C — `cards.dialog`를 둘로 쪼개기 (자기-비판한 §2 검토 포인트의 후속)
3-페이즈 흐름(intro/open/phase-flow/wrap)과 화면 픽 모드는 각자 독립 가치. 한 quest 5-step로 묶으면 화면 픽 모드가 "마지막에 나오는 부록"이 되어 임팩트 약함.

**대안**: `cards.dialog-phases`(3 step, 3-페이즈만) + `cards.dialog-screenpick`(3 step, 화면 픽만, prereq=phases). 둘 다 reward 3d.

→ **결정**: 쪼개기 / 현행 유지

### 제안 D — `widgets.memo`의 목표를 더 좁히기
현재 "정리 도구 팔레트로 마크다운을 정리"는 추상. 구체적으로:

**대안 목표**: "GPT 답변을 메모 카드로 만든 뒤 에디터 도구의 '마크다운으로 정리' 한 번으로 깨진 서식을 복구할 수 있다"

이러면 step이 자연스럽게 짜임: GPT 복사 → 메모 만들기 → 에디터 열기 → 마크다운 정리 클릭 → 결과 확인. cards.memo와 일부 겹치지만 cards.memo는 "메모로 만들기"가 목표, widgets.memo는 "만든 메모를 손볼 줄 안다"가 목표로 분리됨.

→ **결정**: 좁히기 / 현행 유지
